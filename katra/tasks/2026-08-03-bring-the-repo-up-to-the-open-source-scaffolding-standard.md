Match the pattern established in `../mail-muncher`, which was already carrying
the full open-source treatment while katra had a README, a LICENSE and three
design notes.

Delivered: `Makefile` and `.goreleaser.yml` (four targets, both binaries per
archive, cosign keyless signing, Homebrew cask with a graceful no-token path);
CI and release workflows; `CONTRIBUTING.md`, issue and PR templates; a nine-page
GitHub Pages site on katra's own Field Notebook palette; tested examples;
launchd and systemd units; Claude plugin packaging; and a brand kit generated by
`branding/build.py`.

Version is now stamped at link time through `main.version` in both entrypoints,
replacing the hardcoded `"0.1.0"` that `--version` had been reporting since the
rename.

Four defects surfaced while writing it down, which is the argument for writing
it down:

- **`make build` could not work in this repo.** `go build -o katra` tries to
  write over `katra/`, the store directory katra keeps its own log in. Binaries
  now land in `bin/`.
- **Three documented config defaults were wrong** — `accent` is `#e0533d`,
  `commitPrefix` defaults to `katra:`, `description` has a default — and
  `.state/` is gitignored by the memory layer on first use, not by `katra init`.
- **The accent fails WCAG AA as a text colour** at 4.41:1 on paper. It is a UI
  accent; links take `#8a3d24` on light and `#e08a5c` on dark. Measured rather
  than eyeballed; the numbers are in `branding/BRAND.md`.
- **The first CI smoke assertions were wrong**, because `katra init` seeds a
  `hello-katra` draft and a glob `grep -q` passes on the wrong file.

Deliberately omitted, with the reasoning recorded in the README: no Dockerfile
and no MCP-registry listing. katra operates on the working tree, git history and
hooks, so a container means mounting all three for a worse local install — and
the registry indexes by distributable package, so with no image there is nothing
to list.
